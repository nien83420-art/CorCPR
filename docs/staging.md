# Закрытая онлайн-проверка CorCpr

## Прежняя версия

Адрес из README — [v0-corcpr.vercel.app](https://v0-corcpr.vercel.app/). Публичный аудит с этого компьютера остановился на проверке цепочки TLS. Текущий статус сайта, Vercel project ID, deployment ID, тариф и соответствие развёрнутого кода Git-коммиту остаются непроверенными.

Исходный рабочий каталог чистый. Локальные ссылки `main` и `origin/main` указывают на `f546f2078a9453cf77d5c61242037771e6ce04e1`. Этот коммит сохранён в архиве исходников. Он восстанавливает версию из Git. Для точного снимка размещённой версии нужно прочитать в Vercel разделы Domains и Deployments текущего проекта, записать неизменяемый Deployment URL, ID, Git SHA и владельца проекта. Сохранить прежний домен и связанный с ним deployment. GitHub Deployments может содержать только часть истории Vercel.

## Предлагаемая схема

- **Vercel:** отдельный проект `corcpr-staging` без Git-интеграции. Подготовленные исходники можно передать CLI непосредственно в этот проект как Preview. Git-коммит, push и merge для этого пути не нужны. Ссылку для теста брать из созданного защищённого Preview Deployment. Домен старого приложения и его проект остаются на прежней конфигурации.
- **Доступ:** включить Vercel Authentication и Standard Protection до публикации, подтвердить список тестировщиков и протестировать доступ в анонимной сессии. Разрешать доступ конкретным учётным записям Vercel. Избегать shareable-ссылок, исключений защиты, подключения публичного домена и автоматического продвижения в Production. Пакет добавляет `X-Robots-Tag` на все маршруты. [Vercel Deployment Protection](https://vercel.com/docs/deployment-protection), [Vercel Authentication](https://vercel.com/docs/deployment-protection/methods-to-protect-deployments/vercel-authentication), [Vercel CLI Preview](https://vercel.com/docs/projects/deploy-from-cli).
- **Supabase:** новый проект `corcpr-staging` с чистой PostgreSQL. Подтвердить целевой project ref перед применением только файлов `supabase/migrations/*.sql`. Использовать вымышленные учебные профили и результаты. Операции настройки базы выполнять в отдельной от исходного репозитория папке. Исключение MFA из `supabase/local/` отсутствует в пакете исходников и миграциях.
- **Конфигурация:** в Preview environment нового проекта нужны `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY` нового Supabase и новый независимый `CORCPR_GUEST_KEY`. Вводить секреты только в интерфейсе сервиса. Для HTTPS Preview URL настроить точный Auth Site URL и разрешённый URL `/auth/confirm`. Использовать шаблоны из `supabase/templates/` и проверить получение обоих писем.
- **Почта:** для внешних тестировщиков нужен SMTP со своим подтверждённым отправителем. Право настроить SMTP, отправитель и предназначенные для теста почтовые ящики должны быть согласованы отдельно. Встроенная почта Supabase ограничена адресами участников команды. Локальный Mailpit остаётся локальным. [Supabase SMTP](https://supabase.com/docs/guides/auth/auth-smtp).
- **Стоимость:** на Vercel Hobby доступны Standard Protection и Vercel Authentication. У Hobby есть ограничение по внешним участникам. Supabase Free подходит при свободной квоте из двух активных бесплатных проектов и в пределах лимитов. Тариф владельца, свободные места и стоимость SMTP нужно проверить в панели перед изменениями. При нехватке квоты остановиться для согласования суммы и числа тестировщиков. [Vercel Pricing](https://vercel.com/pricing), [Supabase Billing](https://supabase.com/docs/guides/platform/billing-on-supabase).

## Подготовка и критерии допуска

`node scripts/prepare-staging.mjs` создаёт отдельную локальную папку с исходниками и staging-конфигурацией Vercel. Разрешены только исходники приложения, ресурсы и файлы настройки pnpm и Next.js. Git-метаданные, `.env.local`, локальные учётные данные, тесты и любая папка Supabase в пакет не входят. Схему базы и шаблоны почты применяют отдельно к подтверждённому staging project ref.

До передачи адреса тестировщикам проверить HTTPS, закрытый доступ в новом браузере, отсутствие публичного алиаса, отсутствие локальных секретов в пакете и клиентской сборке. На отдельной базе проверить отказ STAFF без MFA, отказ обычному учащемуся в доступе к STAFF и чужим данным, ограничения назначений и отзыв доступа. Затем проверить доставку писем, регистрацию, сброс пароля, вход и выход, сохранение гостевого курса, историю после повторного входа, обязательный первый курс, открытие короткого маршрута после его завершения и запрос разрешения камеры по HTTPS. Использовать как минимум два устройства для проверки входа и чтения сохранённой истории. Проверить прежний URL через панель владельца и сравнить deployment ID до и после staging.

## Решение владельца перед изменениями

Подтвердите создание отдельного Vercel-проекта с защищённым Preview, создание нового Supabase на доступной бесплатной квоте и выбранный SMTP. Нужны существующие доступы к панелям Vercel и Supabase, согласованный список тестировщиков и владелец почтового домена. Вход в панели, ввод секретов и любые платные изменения выполняются только с согласия владельца.
