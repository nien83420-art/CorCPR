# Дорожная карта corCPR

Приоритеты основаны на [контракте](contract.md) и аудите исходников на `f546f20`. Все этапы ниже запланированы. Перед реализацией каждого изменения согласовать краткий план по [правилам проекта](../AGENTS.md). Для проверки использовать изолированный worktree и локальный браузер.

## 1. Воспроизводимый локальный запуск

- **Задачи.** Сверить требования Node.js с закреплёнными версиями Next.js и pnpm, записать фактические версии среды и команду установки. Использовать `pnpm` по `packageManager` и `pnpm-lock.yaml`. После подготовки зависимостей запустить `pnpm dev` и открыть `http://localhost:3000` или адрес из вывода сервера. Отметить расхождение версии Next.js между README и `package.json` для будущей правки.
- **Зависимости.** Рабочая локальная среда Node.js и `pnpm@12.3.4`, доступ к реестру пакетов при установке, браузер и камера для пробного входа в практику. Для модели нужны доступные CDN и Google Cloud Storage.
- **Приёмка.** Другой разработчик может по записанным командам открыть приветствие, пройти до практики и увидеть видеопоток после выдачи разрешения. Версии, URL и ошибки запуска зафиксированы.
- **Проверка.** Повторить запуск в чистом изолированном worktree, проверить путь до первого кадра в браузере и записать вывод сервера и консоли при сбое.

## 2. Базовые ручные проверки

- **Задачи.** Пройти критерии текущего поведения из контракта до изменений логики. Зафиксировать ожидаемый и фактический результат, версии браузера, тип устройства и состояние разрешений. Записать сбои отдельно от неподтверждённых сценариев.
- **Зависимости.** Этап 1, доступная камера, подготовленные сценарии разрешения и блокировки, контрольная серия движений из README.
- **Приёмка.** Есть результаты по полному пути для трёх локалей, ручному и автоматическому завершению, проверке 10 полных циклов и отрицательным случаям счётчика, а также по отказу камеры, потере позы и ошибке загрузки модели. Для каждого сценария зафиксирован статус и, при сбое, шаги воспроизведения.
- **Проверка.** Сверить наблюдения с [критериями контракта](contract.md#критерии-локальной-приёмки-текущего-поведения). Блокировать разрешение через браузер и отдельно имитировать недоступность внешнего ресурса, затем повторить обычный запуск.

## 3. Явная проверка TypeScript

- **Задачи.** Определить воспроизводимую генерацию типов маршрутов для закреплённого Next.js. Учесть, что `next-env.d.ts` импортирует файлы из `.next/dev/types`. Выполнить `pnpm exec tsc --noEmit` после подготовки этих типов. Зафиксировать ошибки исходного состояния, устранить подтверждённые ошибки согласованными изменениями и добавить явную команду проверки типов. Снятие `ignoreBuildErrors` рассмотреть после устойчивого прохождения проверки.
- **Зависимости.** Этап 1, локальные зависимости и воспроизводимая генерация типов в чистом worktree. Для проверки регрессий использовать результаты этапа 2.
- **Приёмка.** Документированная команда запускается из чистого worktree после предусмотренной подготовки и завершается с кодом `0`. Результаты проверки типов и `pnpm build` фиксируются независимо.
- **Проверка.** В чистом worktree подготовить типы, выполнить явную проверку и локальную сборку. Записать команды, вывод при ошибках и коды завершения. Текущий `next.config.mjs` разрешает сборку при ошибках TypeScript.

### 3.1. Первые детерминированные модульные тесты

- **Задачи.** После воспроизводимой проверки TypeScript согласовать инструмент и добавить тесты счётчика, расчёта оценок и поведения при недостатке данных. Использовать фиксированные точки позы, временные метки и статистику сессии. Проверить полные и неполные циклы, известные значения итоговых баллов и `null` для недоступных оценок.
- **Зависимости.** Воспроизводимая проверка типов из этапа 3 и базовые сценарии из этапа 2.
- **Приёмка.** Локальная тестовая команда повторяемо проверяет подсчёт, оценки и недостаток данных без камеры и сетевых запросов. Ожидаемые результаты заданы явно для каждого входа.
- **Проверка.** Дважды выполнить тестовую команду на одних и тех же входах и сравнить результаты. Проверить, что контролируемое нарушение ожидаемого поведения приводит к падению соответствующего теста.

## 4. Надёжность камеры и распознавания

- **Задачи.** Воспроизвести упомянутое в исходниках чёрное видео в Safari. Проверить получение разрешения, запуск воспроизведения, повторную попытку, прерывание потока, фон и возврат на вкладку, отказ GPU и недоступность модели или WASM. По результатам исправить подтверждённые сбои и предусмотреть понятное восстановление или выход.
- **Зависимости.** Этапы 1–3, камера, Safari и браузер на Chromium для сравнения, управление разрешениями и сетевыми запросами к ресурсам модели.
- **Приёмка.** Для проверенных браузеров после разрешения отображается первый кадр и запускается распознавание. При воспроизведённых сбоях пользователь получает понятное состояние и рабочий путь восстановления или выхода. После завершения и повторных попыток старые треки остановлены.
- **Проверка.** Повторить матрицу сценариев на указанных браузерах. Сверить наличие кадров, состояние треков, загрузку модели и переходы интерфейса. В отчёте указать версии браузеров и сценарии, которые не удалось воспроизвести.

## 5. Достоверность учебной обратной связи

- **Задачи.** Сопоставить подсказки с наблюдаемыми событиями счётчика и проверки позы. Проверить приоритет подсказок, обработку шума, потери позы и недостатка данных. Сверить подписи темпа и общего балла с расчётом. Перед изменением пользовательского текста передать `pushDeeper`, `releaseFully`, `goodCompression` и интерпретацию результатов эксперту.
- **Зависимости.** Базовые наблюдения этапа 2, проверка типов этапа 3, воспроизводимая работа камеры по этапу 4 и экспертная оценка формулировок.
- **Приёмка.** Для проверенных событий показаны соответствующие учебные подсказки. При потере позы или недостатке данных интерфейс не выдаёт положительную оценку на основании отсутствующих наблюдений. Экспертное решение по отмеченным фразам зафиксировано. Тексты не обещают измерение глубины, силы или клинической эффективности.
- **Проверка.** Сопоставить подсказки и результаты с контрольными сериями полных и неполных циклов, согнутыми локтями, разнесёнными запястьями, краткой и длительной потерей позы и ранним завершением. Сверить формулировки с решением эксперта.
